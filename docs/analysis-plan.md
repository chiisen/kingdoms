# 專案分析與規劃 / 三分天下 · 百將風雲

本文件記錄這次「複刻」的分析與規劃過程：先拆解參考專案，再決定技術選型、模組切分與驗證方式。

參考專案：[MartinDelophy/awesome-gpt-6-astra · works/three-kingdoms](https://github.com/MartinDelophy/awesome-gpt-6-astra/tree/main/works/three-kingdoms)

---

## 1. 需求分析

### 1.1 參考專案是什麼

一款原創三國題材回合制策略網頁遊戲（v0.2.0）。玩家從曹操、劉備、孫權三方擇一，在 15 座城池之間經營錢糧、調兵攻城，最終佔領全部城池。共 108 位武將（每方 36 位），每人對應一張生成的獨立頭像。

### 1.2 功能清單（複刻目標）

| 面向 | 具體內容 |
| --- | --- |
| 地圖 | 15 城、21 條道路；魏（洛陽、鄴城、許昌）、蜀（西涼、漢中、成都）、吳（下邳、建業、柴桑）各 3 城，群雄 6 城；四方對稱開局 |
| 資源 | 金錢與軍糧；回合結束入庫，兵卒每回合耗糧，糧盡減員 8% |
| 城池指令 | 開墾農田、發展商貿、徵募兵卒、操練軍隊、修築城防；每次消耗 1 政令 |
| 武將 | 統率／武力／智略三圍、定位與專長、統兵上限、休整 2 回合、智略減費與節糧 |
| 出征 | 僅能沿道路至相鄰城池（含友軍增援）；留守 1,000 兵；出征軍糧；勝敗預測 |
| 戰鬥 | 攻擊力 = 兵力 × 統軍係數 × 士氣係數；守方受城防加成；勝方占城、安民 2 回合產出減半 |
| 政令 | 依城池數成長：3 城 3 道、8 城 4 道、13 城 5 道 |
| AI | 內政、徵兵、增援、協同攻城（多路同時出兵）；以回合開始情報規劃，不作弊 |
| 存檔 | localStorage 自動存檔、JSON 匯出／匯入、v1→v2 遷移與嚴格欄位驗證 |
| 介面 | 天下地圖（縮放、全屏）、武將圖鑑（搜尋／勢力篩選／詳情）、戰報、軍師錦囊（玩法＋存檔） |
| 其他 | 音效提示、自動擇優任命執行武將、觸屏與鍵盤操作 |

### 1.3 素材清單（沿用）

- `public/terrain.jpg`：水墨風格戰略地形圖（819 KB）
- `public/portraits/{wei,shu,wu}-v2.jpg`：三張 1254×1254 的 6×6 頭像圖集，每格一位武將（各約 700 KB）
- 前端以 CSS `background-position` 裁切單格顯示，蜀國圖集列高不同，需按實際列邊界定位

## 2. 技術選型

參考專案使用 `vinext`（RSC 框架）＋ Base UI／shadcn 元件。複刻時改用更通用、相依更少、可長期維護的組合：

| 項目 | 參考專案 | 本專案 | 選用理由 |
| --- | --- | --- | --- |
| 建置 | vinext 1.0.0-beta.9 | Vite 8 | 穩定的 SPA 建置；本遊戲無伺服器端需求 |
| 框架 | React 19 + RSC | React 19（純客戶端） | 遊戲狀態全在使用者瀏覽器，`'use client'` 無意義 |
| 樣式 | Tailwind CSS 4 + shadcn 主題 | Tailwind CSS 4（`@tailwindcss/vite`） | 保留原主題變數與全部遊戲 CSS，移除 `shadcn/tailwind.css` 相依 |
| UI 元件 | `@base-ui/react` + shadcn 產生器 | 自製 7 個 primitive | 對外 API 與 `data-slot` 一致，省去兩個重量級相依 |
| 圖示 | lucide-react | lucide-react | 相同 |
| 測試 | node:test + esbuild 打包 | node:test + esbuild 打包 | 相同作法，直接在 Node 內驗證 TypeScript 引擎 |
| 部署 | Vercel（`dist/client`） | 靜態 `dist/`，可放任何靜態主機 | 簡化 |

## 3. 模組設計

```
src/
├── main.tsx            掛載 React
├── App.tsx             入口（對應上游 app/page.tsx）
├── styles/
│   ├── globals.css     遊戲主題與全部版面樣式（移植自上游，改寫 import 來源）
│   └── ui.css          自製 UI primitive 的基礎樣式
├── lib/utils.ts        cn() 類名合併
├── components/ui/      Dialog / AlertDialog / Select / Slider / Tabs / Input + modal 共用底座
└── game/
    ├── engine.ts       純函式遊戲引擎：地圖、經濟、戰鬥、AI、存檔驗證與遷移
    ├── officers.ts     108 位武將資料與圖集映射
    ├── Portrait.tsx    以 CSS 裁切圖集單格
    └── Game.tsx        介面：地圖、城池面板、圖鑑、戰報、對話框
```

### 3.1 分層原則

- **引擎（`engine.ts`）與介面完全分離**：所有動作（`act`、`march`、`endTurn`、`autoOrders`）都是 `Game → Game` 的純函式，先複製狀態再改動，失敗時 `throw` 中文錯誤訊息。因此 UI 只需 `try/catch` 顯示訊息，且測試能在 Node 中直接跑完整戰局。
- **資料驅動**：城市座標、道路、武將、指令成本都集中在 `engine.ts` / `officers.ts`，介面只讀取。
- **存檔即狀態**：`Game` 物件本身就是存檔格式（`version: 2`），`loadGame()` 逐欄位驗證並拒絕竄改或損壞的存檔。

### 3.2 UI primitive 的替換策略

上游 7 個 `components/ui/*` 依賴 Base UI，對外介面為：

- `<Dialog open onOpenChange>` + `DialogContent/Title/Description`
- `<AlertDialog>` 同上，但點擊遮罩不關閉
- `<Select value onValueChange>` + `Trigger/Value/Content/Item`（自帶錨定彈出層）
- `<Slider value={[n]} onValueChange>`、`<Tabs defaultValue>`、`<Input>`

本專案以 `modal.tsx` 為共用底座（portal、焦點鎖定、Esc 關閉、焦點還原）自行實作，並保留**相同的 `data-slot` 名稱**（`dialog-content`、`select-item`、`slider-thumb`…），因此移植過來的遊戲 CSS 完全不用修改即可生效。

實作時發現並修正一個分層問題：Select 彈出層與 Dialog 同時監聽 `keydown`，單次 Esc 會同時關閉兩者。改為以開啟中的彈出層計數（`usePopupLayer`）判斷——有彈出層時 Dialog 不處理鍵盤，Esc 先關彈出層、再關對話框。

## 4. 施工步驟

1. 取得參考專案原始碼與素材，逐檔閱讀（引擎、武將資料、介面、樣式、測試、文件）。
2. 建立 Vite + React 19 + TS + Tailwind 4 專案骨架；下載地形與三張頭像圖集到 `public/`。
3. 移植 `engine.ts`、`officers.ts`（規則與資料）；`Game.tsx` 只需移除 `'use client'` 與 `__TERRAIN_URL__`，改用 `import.meta.env.BASE_URL`。
4. 移植 `globals.css`，只調整開頭 import；遊戲樣式原樣保留。
5. 自製 UI primitives（`components/ui/`）並補 `ui.css`。
6. 移植 `scripts/test-engine.mjs`，把打包入口改為 `src/game/*`，並為 `Portrait.tsx` 的 `import.meta.env.BASE_URL` 加上 `define`。
7. 逐項驗證：`npm test` → `npm run typecheck` → `npm run build` → 瀏覽器實測。

## 6. 已知限制與後續

- **素材與規則來自上游**：地形與頭像圖集沿用參考專案，武將數值與道路為上游自訂規則，非《三國志11》原版資料。上游未對遊戲原始碼個別授權（僅說明集合內原創文字與圖像依 CC0 釋出），因此本專案保留完整出處標註，見 `THIRD_PARTY_NOTICES.md`。
- **AI 為規則式**：靠 `isMusterTurn` 決定集結回合、以回合開始情報估算守軍，沒有搜尋或學習；長期勝率未經人類對局驗證（上游 `docs/reference/balance-v2.md` 亦如此聲明）。
- **響應式僅到平板寬度**：`min-height: 680px` 的桌面版型，窄螢幕需捲動城池面板；未針對手機直向優化（與上游一致）。
- **未移植的項目**：上游的 Vercel／Sites 部署設定與 `oxlint`/`oxfmt` 檢查；本專案改用 `tsc --noEmit` 與 `npm test` 作為品質關卡。

## 7. 第二輪：配樂、音效與數值演出

### 7.1 需求

1. 要有三國志風味的背景音樂。
2. 點擊功能時要有音效。
3. 功能點擊後要有數值變化的演出效果。

### 7.2 配樂與音效的取捨

不能直接取用遊戲配樂（版權），參考專案本身也只用合成提示音，因此選擇**以 Web Audio API 即時合成**：不新增任何音檔、不增加網路請求、沒有授權問題，而且樂曲是可讀的資料而非黑盒音檔。

設計要點：

- **調式**：D 宮五聲音階（宮商角徵羽，`PENTATONIC = [0, 3, 5, 7, 10]`），音階外的音一律不出現，這是「中國風」最直接的來源。
- **編制**：撥弦（箏／琵琶，加性諧波＋短促噪音起振）、弓弦（鋸齒波＋低通＋揉弦顫音，用於 B 段）、低音、編鐘（非諧分音＋長衰減）、鼓（正弦下滑＋噪音瞬間）。
- **結構**：20 小節、76 BPM、約 63 秒循環。A 段 8 小節留白、琵琶在第 5 小節加入；B 段 8 小節上八度改由弓弦主奏、鼓點加密；4 小節過門後接回開頭，段末有滾奏與編鐘。
- **排程**：`scheduleBars()` 是純函式，同時被即時播放器（前瞻 1.2 秒、每 60ms 補排）與離線檢驗使用，因此「驗到的」就是「聽到的」。
- **播放規則**：受自動播放限制，音樂在第一次手勢後才啟動；分頁進背景暫停；開關存於瀏覽器。

### 7.3 演出的作法

- 新增 `AnimatedNumber`：以 `requestAnimationFrame` 把顯示值滾向目標值，並記錄差額產生浮標。
- 以 CSS 類別處理其餘效果（差額浮動、數值泛色、進度條伸縮泛光、政令格彈跳、按鈕閃爍、攻克光暈與旗幟、軍情滑入），並在 `prefers-reduced-motion` 時全部停用。
- 切換城池時以 `key={city.id}` 讓元件重掛，避免把「換看另一座城」誤判成數值變化而跳出假差額。
- 讀取存檔或另啟新局時以 `campaign` 序號重掛總計數字，避免一次跳出 `+36,017` 這種假的差額。

### 7.4 這一輪抓到的問題

| 問題 | 症狀 | 修正 |
| --- | --- | --- |
| 分解和弦走音 | `B_BASS.map(arpeggioBar)` 把陣列索引當成 gain 傳入，B 段和弦音量變成 0～7（會嚴重爆音），且伴奏音高脫離五聲音階 | 改用命名回呼 `(root) => arpeggioBar(root)`；分解和弦改由調式音級產生（`pentatonicRun`），任何和弦根音都不會走音 |
| 音階外音 | 固定音型加上非主音根音時會產生 F#／E 等音階外音 | 同上，並補上「所有音高必須在五聲音階內」的自動測試 |
| 背景分頁數字卡住 | `requestAnimationFrame` 在分頁不可見時不觸發，數字會停在舊值 | 動畫之外再加上計時器保險，逾時直接落到真值 |
| Esc 一次關兩層 | Select 彈出層與 Dialog 同時攔 `keydown` | 以 `usePopupLayer` 計數，彈出層開啟時 Dialog 不處理鍵盤 |
| Tailwind 掃到輸出目錄 | `dist/` 被當成掃描來源，CSS 由 47KB 膨脹到 63KB | 加入 `.gitignore` |

### 7.5 這一輪的驗證

- `npm test`：引擎 23 項 ＋ 音訊 9 項（樂曲結構、五聲音階約束、可重現性、排程時間窗、16 個音效都能產生發聲節點、靜音不崩潰）。
- 離線渲染：以 `OfflineAudioContext` 走真實合成路徑，四個段落 RMS 0.039～0.062、峰值 0.28～0.41，無爆音；即時播放時節點數隨時間成長，`stopMusic()` 後停止成長。
- DOM 取樣：徵兵後讀到五個差額浮標與正確數值（`−531`／`−1,500`／`+2,500`／`+2,500`／`−1`）、按鈕閃爍類別、士氣條轉紅；回合結算後讀到歲入差額與政令 `+3`、AI 攻克城池的 `just-changed` 標記；音效開關會寫入 `sanguo-jiangshan-audio` 並在重整後沿用。
- 限制：自動化瀏覽器分頁不推進動畫時鐘（`requestAnimationFrame` 不觸發、CSS 動畫停在 0%），因此**無法在此環境目視確認動畫的流暢度**；改以凍結在時間軸中點的方式截圖檢視版面與配色，並確認動畫名稱與播放狀態正確。

## 8. 第三輪：地圖上的數值演出

### 8.1 需求

地圖上的數值有異動時也要有演出效果。

地圖上可見的數值只有三處：各城池下方的駐軍數、左下角圖例的各勢力城池數、行軍旗標上的兵力。

### 8.2 作法

- 把城池駐軍抽成 `CityTroops` 元件（`src/game/Game.tsx`），內部用 `useValueDelta` 取得增減方向，配上共用的 `AnimatedNumber`：數字滾動、顏色泛綠／泛紅、並浮出差額。
- 差額浮標在地圖上改為**向下、水平置中**：`.city-troops .delta-chip` 覆寫 `top`／`left`，並另寫一組 `delta-float-center` 關鍵影格，讓位移包含 `translate(-50%)` 置中，否則動畫會把置中位移蓋掉（浮標會水平跳開）。放在城池下方而非上方，是因為上方會被城池旗標蓋住。
- 圖例數字改用 `LegendCount` 元件：只滾動與泛色，不浮差額，避免下方資訊列過於吵雜。
- 行軍旗標加上 `token-spawn`：建立時由小放大彈出，之後接續原有的 `token-pulse` 脈動。兩個動畫都改寫 `transform`，因此把 `token-spawn` 排在後面讓它在 0.46 秒內優先，之後交還給無限循環的脈動。
- 抵達時的表現不需要額外處理：部隊併入城池後，目的城池的駐軍數自然觸發同一套滾動與差額。

### 8.3 這一輪的驗證

- 載入存檔時地圖上沒有任何差額浮標（`campaign` 序號生效），15 座城池都直接顯示正確數字。
- 結束回合後讀到：漢中 `is-up` `+13,500`、洛陽 `is-down` `−13,500`、另一城 `is-up` `+4,500`、戰損 `−710`；浮標幾何為「水平偏移 0px、位於標示下方 1px」；圖例 `刘备 3→4` 帶 `flash-up`、`群雄 6→5` 帶 `flash-down`；1.2 秒後所有浮標與類別自動清除。
- 下達出征後，行軍旗標的 `animation-name` 同時包含 `token-pulse` 與 `token-spawn`，出發城池讀到 `is-down` `−6,000`。
- 型別檢查與建置通過；引擎 23 項與音訊 9 項測試不受影響。
- 限制：此環境的瀏覽器面板不會重繪（截圖逾時或出現拼接殘影），地圖演出的**視覺外觀仍建議在一般瀏覽器視窗確認**；程式面已驗證類別、差額文字、浮標幾何與動畫名稱皆正確。

## 10. 第五輪：補上介面與文字測試

### 10.1 需求與選型

前三輪的驗證方式是「Node 測純邏輯 ＋ 瀏覽器人工驗證」，介面層沒有自動化測試。權衡後採兩段式：

1. **vitest ＋ jsdom ＋ testing-library**（主要投資）：還沒測到的東西九成是 React 狀態邏輯（差額方向、重掛時機、焦點與 Esc 分層、鍵盤操作），jsdom 就能測，毫秒級、不需下載瀏覽器。
2. **零成本的繁簡不變式測試**：`opencc-js` 已經是 devDependency，把每個介面原始碼轉一次、比對是否相同即可擋住簡體字混入。
3. **Playwright 暫緩**：它才能驗證渲染外觀與真實音訊，但成本高（瀏覽器二進位檔、較慢），而且本專案所處的自動化瀏覽器面板**不會推進動畫時鐘**（`requestAnimationFrame` 不觸發、截圖逾時或殘影），動畫類斷言容易變成 flaky。純視覺維持人工確認。

### 10.2 設定

- `vite.config.ts` 改用 `vitest/config` 的 `defineConfig`，加入 `test` 區塊（jsdom、setupFiles、include `src/**/*.test.{ts,tsx}`）。
- `src/test/setup.ts`：每個測試前後清理 DOM 與 localStorage、重設 `matchMedia`；`src/test/motion.ts` 提供 reduced-motion 切換（jsdom 沒有 `matchMedia`）。
- 測試檔放在 `src/**/__tests__/`，因此在 `tsconfig` 的 include 之內，`tsc --noEmit` 也會檢查測試碼。
- `npm test` 依序跑四套：`test:engine`（23）→ `test:audio`（9）→ `test:text`（3）→ `test:ui`（30），共 65 項。

### 10.3 為了可測試性做的一處調整

對話框的 Tab 焦點鎖定原本用 `element.offsetParent !== null` 過濾可見元素，但 jsdom 沒有排版，`offsetParent` 永遠是 null，會讓焦點清單為空而無法測試（真實瀏覽器不受影響）。改成「可見清單為空時退回全部候選」，瀏覽器行為不變，測試環境也能走同一條路徑。

### 10.4 這輪抓到的真實缺陷

| 缺陷 | 由哪個測試抓到 | 修正 |
| --- | --- | --- |
| 主選單按鈕寫成「起兵出**徵**」 | 文字不變式測試（OpenCC 轉換後仍不同） | 改回「起兵出征」；另加「徵只用於徵兵」的專項檢查 |
| 另啟新局後，城池駐軍浮出假的 `−2,500` | 介面整合測試（斷言換局後不得有差額浮標） | 駐軍計數原本只以 `city.id` 為 key，補上 campaign 序號；士氣／城防與農業／商業一併處理 |
| 我第一版測試太弱：突變測試沒咬住 | 我自己用突變測試檢查時發現 | 差額斷言改在浮標存在時檢查（原本在浮標過期後才斷言）、按鈕閃爍改在 760ms 視窗內斷言 |

第三項值得記下來：測試寫了不代表測得住。我對兩條最重要的守衛做了突變測試——把 campaign key 拿掉、把 Esc 守衛拿掉——確認對應測試會失敗，才敢說那兩條是真的有效。

### 10.5 仍未自動化

- 渲染出來的版面與動畫流暢度（需要會推進動畫時鐘的瀏覽器；以人工確認）。
- 可聽見的音訊（以 `OfflineAudioContext` 離線渲染量測音量，屬於人工驗證而非 CI 測試）。
- 遊戲規則層的整合仍以引擎測試為主；UI 測試只覆蓋介面契約與演出邏輯，不重複驗證規則數值。

## 11. 第六輪：lint、簡繁搜尋、預設靜音

### 11.1 需求

開啟後共 39 個警告，其中真實問題都修掉了：

- `eslint/no-shadow` ×14：`src/components/ui/slider.tsx` 的解構改名（`min`/`max`/`step` → `low`/`high`/`size`）、`Game.tsx` 的 `city` 參數改名，以及 `engine.ts` 八處回呼參數（`c`/`o`/`a`）改成 `city`/`officer`/`army`/`x`/`y`。引擎的改名以 23 項引擎測試＋32 項介面測試確認行為不變。

### 11.3 簡繁雙向搜尋（第 8 項）

需求是「可以轉換，但要保證簡繁都能搜尋到」。若在瀏覽器端引入 OpenCC，函式庫與字典會明顯增加 bundle；因此改為**在撰寫期產生對照表**：

- `scripts/build-search-forms.mjs` 用 esbuild 打包 `officers.ts` 取得結構化資料，再用 OpenCC（`tw` → `cn`）產生每位武將「姓名＋定位＋專長」的簡體寫法，寫入 `src/game/search-forms.ts`（108 筆、約 8 KB，內含註解標示為產生檔）。
- 圖鑑過濾改成比對「繁體欄位 ＋ 該武將的簡體寫法」，因此繁體查詢與簡體查詢都會命中同一位武將；執行期不需要任何轉換函式庫。
- `scripts/test-text.mjs` 新增兩項守衛：產生檔是否與 `officers.ts` 同步（不同步就提示重跑產生指令），以及幾個「每個字都不同」的名字（諸葛亮／趙雲／張飛／龐統／黃蓋）確實有簡體寫法。

### 11.4 音效預設靜音（第 10 項）

`readStoredSound()` 在沒有紀錄時改回傳 `false`（原本是 `true`），因此首次載入是靜音，由右上角喇叭開啟；開啟的那次點擊同時滿足瀏覽器的自動播放限制。音訊測試與介面測試各加一條斷言「未設定時為靜音」「開關會寫入偏好」，README 的播放規則也同步更新。

### 11.5 記錄 issue（第 5 項）
